# 语言支持

[English](languages.md) · **简体中文**

为了更好地做代码分析，Clew 会针对不同语言的特性，提供贴合它的支持。目前 Clew 提供的功能完整支持 Rust、Python、TypeScript/JavaScript、Go、Dart、Java、Kotlin、Scala、C、C++、C#、PHP、Ruby、Erlang、Elixir、Haskell 和 Zig；Lean 4 和 SQL 支持其中的大部分功能；对其余语言目前也提供了一些基础支持，如语法高亮。未来会支持更多语言。

**设置 → 语言服务器** 会针对当前打开的项目，显示每种语言的语言服务器及其状态，并让你为每种语言做设置——每项设置都先显示当前生效的内容，再列出可选项：

- **Python** —— 语言服务器和调试器所使用的解释器，以及由谁指定（你的选择、项目的 `.clew/lsp.toml`、为项目找到的环境）。可以从 Clew 找到的环境中另选一个（项目自身的、Poetry、Pipenv、Hatch、PDM、conda、pyenv、uv，或 `PATH` 上的 `python3`），也可以直接填写路径。语言服务器默认是 pyright，也可以在 **任意语言** 中另选：basedpyright、pylsp、jedi-language-server、ruff、ty 和 pyrefly 都会以各自提供服务的方式运行，并在各自读取的位置得到解释器和环境中的包。
- **Rust** —— rust-analyzer 加载项目时启用的 Cargo features（从各 package 的 `Cargo.toml` 中列出全部 features；也可以全部启用，可选是否带默认 features），以及检查所针对的 target。
- **Go** —— gopls 和调试器构建时使用的 build tags（列出项目中 `//go:build` 行用到的 tags），以及按哪个 `GOOS`/`GOARCH` 阅读项目。
- **C 和 C++** —— clangd 使用的 `compile_commands.json`（列出 CMake、Meson 等在项目中生成的那些），以及编译数据库未覆盖的文件所用的编译参数（如 `-DDEBUG -Iinclude -std=c++20`）。
- **Lean 和 Dart** —— 语言服务器所用的工具链：elan 安装的各个工具链（项目 `lean-toolchain` 指定的排在最前）、Flutter SDK 以及 fvm 管理的各个版本（项目指定的排在最前）。
- **TypeScript 和 JavaScript** —— 语言服务器所运行的 TypeScript：默认使用 Clew 自带的版本，除非你主动选择，否则绝不会使用项目自带的版本（列表中会标出它的版本，并注明它会运行项目自身的代码），也可以选择全局安装的版本。
- **Zig** —— zls 所使用的 `zig` 编译器：zvm 和 zigup 管理的各个版本（项目 `build.zig.zon` 要求的版本排在最前），或你指定的编译器。zls 会选用为这个 Zig 构建的版本——每个 zls 只适配构建它的那个 Zig 版本——所以用 Zig 0.15 的项目得到 zls 0.15.1，用 0.17 的得到 zls 0.17.0（0.13 到 0.17 的各版本均会下载并按摘要校验），除非项目的 `lsp.toml` 指定了版本。
- **Java** —— Eclipse JDT 语言服务器构建项目所用的 JDK：本机上的各个 JDK（`JAVA_HOME`、`/usr/lib/jvm`、macOS、SDKMAN!、IntelliJ、asdf、mise 和 Homebrew 安装的），构建要求的 Java 版本（`.java-version`、`.sdkmanrc`、Gradle 工具链、`pom.xml`）对应的排在最前。
- **PHP** —— intelephense 按哪个 PHP 版本解读代码（`composer.json` 允许的最低版本排在最前）。
- **C#** —— csharp-ls 打开的解决方案：项目根目录及下一级目录中的 `.sln` 和 `.slnx` 文件。
- **Kotlin、Scala 和 Elixir** —— 要运行的语言服务器：JetBrains 的 Kotlin LSP（或社区的 kotlin-language-server）、Metals（在 Coursier 安装的位置查找）、Expert（或 ElixirLS）；否则用你 `PATH` 上的。
- **Ruby、Erlang 和 Haskell** —— 选用哪个 Ruby 的 Ruby LSP（rbenv、chruby、asdf、mise、RVM 安装的；项目 `.ruby-version` 指定的排在最前），以及要运行的 ELP 和 Haskell 语言服务器（ghcup、Stack、Cabal 安装的），或 `PATH` 上的。
- **任意语言** —— 使用你自己的语言服务器程序：另一个版本的 Clew 自带服务器、另一种服务器，或为 Clew 尚无服务器的语言指定一个。会构建项目的服务器在构建前仍会先征得你的同意。打开 **与该语言的服务器同时运行** 后，这个程序会作为第二个服务器与该语言自己的服务器一起运行（例如在 pyright 旁边运行 ruff）：它会收到同样的文件，它的警告与第一个服务器的警告一起显示——加下划线、计入状态栏、悬停时说明——而跳转到定义、查找引用和悬停文档仍由第一个服务器提供。

以上内容都只通过读取文件得到——不会运行任何程序；远程项目则在其所在主机上查找。这些选择保存在 Clew 自己的数据目录中，只对本机上的这个项目生效，绝不会写入项目，优先于项目的 `lsp.toml`，并同样作用于编辑器的语言服务器、调试器以及 Ask 的代码工具。

某种语言的服务器还没有安装时，Clew 会先问你，再下载它自己的那一份。如果这个服务器程序已经在你的 `PATH` 上——rustup 装的 rust-analyzer、你自己装的 clangd——提问里也会给出它；能回答版本号的会先问它的版本，这样版本管理器为一个并未安装的工具留下的垫片（shim）就不会被提供（TypeScript 的从不提供：Clew 自带的服务器固定了它所运行的 TypeScript，而你自己的服务器会从项目里取 TypeScript）。点击 **使用已有的**，它就成为这门语言的服务器，和在这里选中它一样，什么都不会下载。你自己装的 pyright 或 basedpyright 会直接使用：不提问、不下载，也不需要 Node；只有项目固定了 pyright 的版本时才会安装那个版本。

构建因此不会编译的代码会在阅读时变暗：Rust 中依赖未启用 feature（或其他平台）的 `cfg` 项、`//go:build` 行或 `_windows.go` 这类文件名所排除的 Go 文件，按平台和 `-D`/`-U` 参数会被预处理器丢弃的 C/C++ `#if`/`#ifdef` 分支，Zig 中基于 `builtin.os.tag` 或 `builtin.cpu.arch` 的 comptime `if`/`switch` 分支里编译器不会为该平台分析的部分，C# 中依据文件自身 `#define` 的符号判定不成立的 `#if` 分支，Haskell 中（启用了 CPP 的文件）基于 `<os>_HOST_OS` 和 `<arch>_HOST_ARCH` 的 CPP `#if` 分支，以及 Erlang 中依据文件自身 `-define` 的宏判定不成立的 `-ifdef`/`-if` 分支。与平台有关的判断，以状态栏中选定的平台为准。只有确定不会编译的代码才会变暗——可能由其他 package 启用的 feature、可能由头文件定义的宏，都不会被处理。

- **SQL**：大纲列出 schema 中的表（及其列）、视图、函数、触发器和类型，并以其上方的 `--` 注释作为文档；类型图会按外键把表连接起来（无论外键写在表定义中，还是像 `pg_dump` 那样写在同一文件的 `ALTER TABLE` 里），并把每个视图连向它所查询的表。没有语言服务器时，由项目的数据库结构在代码中作答：指针（Alt）或光标处（显示信息）下的表或列会显示结构对它的描述 —— 表的列、键、索引、策略和触发器；列的类型、默认值、注释和引用 —— 转到定义会跳到创建它的语句。名称按书写方式解析（`schema.table`、`alias.column`），适用于 SQL 文件、Prisma schema 以及其他代码中的 SQL 行。薄弱点会列出没有主键的表、没有索引的外键、在同一 schema 其他表已启用时仍关闭的行级安全，以及删除数据、添加无默认值的 `NOT NULL` 列或阻塞表写入（未使用 `CONCURRENTLY` 建索引、修改列类型）的迁移。
- **光标处的测试，覆盖所有编译型语言和 BEAM 语言**：Go 的 `func TestX`（以及基准测试、模糊测试和示例）、Java、Kotlin 和 Scala 里 JUnit 的 `@Test` 方法、ScalaTest 和 MUnit 的 `test("…")`、xUnit 的 `[Fact]` 和 `[Theory]`、NUnit 的 `[Test]` 和 MSTest 的 `[TestMethod]`、Dart 的 `test` 和 `group`（以及 Flutter 的 `testWidgets`）、RSpec 的 `it` 和 `describe`、Minitest 的 `test_x`、Zig 的 `test` 块、EUnit 的 `_test` 函数和 Common Test 套件里的用例、ExUnit 的 `test` 和 `describe`、hspec 和 Tasty 的测试、GoogleTest 的 `TEST` 和 Catch2 的 `TEST_CASE` 都会在行号旁标出；程序的入口也会标出——`package main` 中 Go 的 `func main`、C 和 C++ 的 `main`、Java 的 `static void main`、Kotlin 的 `fun main`（顶层的，或 object 中带 `@JvmStatic` 的）、Scala 的 `def main`、`@main` 或 `object … extends App`、C# 的 `Main` 或程序的顶级语句、Dart 和 Zig 的 `main`、`Main` 模块中 Haskell 的 `main`、Erlang 模块导出的 `main/1`，以及 Ruby 的 `if __FILE__ == $0`——点击它旁边的 ▶，会像没有启动配置时的“运行”和“调试”那样运行或调试这个文件的程序，不管启动配置指定的是什么（Go 程序运行结束时显示 Delve 报告的退出码；Flutter 应用则在 Flutter 自己的调试适配器下运行：应用有本机桌面平台时在本机桌面上运行，否则有 Web 平台时在浏览器中运行，否则在 Flutter 列出的第一个设备上运行）；**Run Test** 用项目自己的命令、在项目所在的地方运行光标处的测试（或它所在的组，或整个文件）：在模块里执行 `go test -run`，JUnit 用 Gradle（优先用它的 `gradlew`）或 Maven（`mvnw`），Scala 用 sbt、Mill 或 scala-cli（MUnit 的单个测试按全名、ScalaTest 的按 `-z`、套件按其类、文件按其中的套件），`dotnet test --filter` 按测试的全名，`dart test` 或 `flutter test` 按名字，`rspec file:line`（有 Gemfile 时经由 Bundler），Rails 的 `rails test file:line` 或 Minitest 的 `-n`，`zig test --test-filter`，rebar3 的 `eunit --test` 或 `ct --case`，`mix test file:line`，Cabal 或 Stack 配合 hspec 的 `--match`（Tasty 用 `--pattern`），以及在 CMake 构建目录里执行 `ctest -R`。**调试测试**在该语言的调试器下运行同一条命令，并在你的断点处暂停：Go 用 Delve 的测试模式，Ruby 在 rdbg 下运行（RSpec、Rails 和 Minitest 均可），Dart 和 Flutter 用各自的测试适配器，JUnit、MUnit 和 ScalaTest 通过 Gradle、Maven、sbt、Mill 或 scala-cli 运行、测试 JVM 置于 Clew 的 Java 调试器之下（sbt 的测试 JVM 为此单独派生，调试代理只加在它上面；scala-cli 的则通过 `--java-opt` 传入；Mill 的测试以 `testLocal` 在 Mill 自己的 JVM 中运行，该 JVM 启动时在项目的 `.mill-jvm-opts` 之外加上调试代理）（它按源文件找到 Kotlin 或 Scala 文件编译出的类，例如 `Cart.kt` 的 `CartKt`，并能在任意模块中找到暂停帧所在的文件，如 `core/src/main/scala` 或 Mill 的 `foo/src`），CTest 的测试以其自己的程序和参数（即 `ctest --show-only` 列出的）在 lldb 下运行，Zig 的测试则为它专门构建——能单独构建时单独构建，否则像下文的 Zig 程序那样由项目的 `build.zig` 构建，测试二进制只保留这一个测试。即使调试器不报告退出码（Delve 和 rdbg 就不报告），运行结束时也会给出测试结果——从测试运行器的最后一行读出。测试运行器输出的颜色（sbt 的、MUnit 差异的）在运行输出中显示为颜色，而不是转义码。EUnit 和 ExUnit 的测试在 OTP 解释器（Clew 的 Erlang 调试器）下运行：EUnit 用它自己对该测试的调用（文件以 `TEST` 宏编译），ExUnit 按 `mix test file:line` 的方式运行，并先编译测试文件，因此测试本身中的断点和它所调用代码中的断点都会命中；停在断点处的测试在你阅读时不会超时：本次运行取消了 EUnit 的五秒和 ExUnit 的一分钟限制（测试自己设定的超时仍然有效）。由测试运行器的调用打开的代码块而不是函数构成的测试——ExUnit 的 `test` 和 `describe`、RSpec 的 `it` 和 `describe`、Zig 的 `test`、MUnit 和 ScalaTest 的 `test(…)`、Kotest 的测试、GoogleTest 的 `TEST`（命名为 `Suite.Name`）、Catch2 的 `TEST_CASE`、Dart 的 `test` 和 `group`、hspec 的 `it`——会出现在大纲中，并在调用图中作为其所调用代码的调用者，因此只被测试调用的函数算作被调用，不会被列为可能的死代码；Elixir 模块的函数以 `Cart.add(…)`、Erlang 模块的函数以 `cart:add(…)` 的形式从任何模块都能找到，无需导入（别名的最后一段也可以）；类的函数同样可以从它旁边按类名找到，无需导入——Java、Kotlin 和 Scala 中同一个包里的类，C# 中同一个命名空间里的类，Ruby 中已 require 的类；C 或 C++ 的函数或方法则通过声明它的头文件找到，无论它定义在哪里（`main.cpp` 中的 `c.add(…)` 经由 `cart.hpp`——直接包含或经由另一个头文件包含——找到 `cart.cpp` 中的 `int Cart::add`），但不会找到其他文件中的 `static` 函数。调用会按语言本身的规则落到目标上：Go、Java、Kotlin、Scala 文件无需 import 就能调用同一个包里其他文件的函数（Go 按所在文件夹，JVM 语言则不论文件放在哪里——Kotlin 和 Scala 的包按文件声明的 `package` 找到，Scala 文件的链式 package 子句——先 `package cats.effect` 再 `package example`——也让外层包的成员可见），C# 文件则是同一命名空间及外层命名空间的（带字节顺序标记保存的文件——Visual Studio 就这样保存——也在它的命名空间里）；方法调用按值声明的类型解析——参数、字段（`private final OwnerRepository owners;`、Kotlin 构造函数里的 `val`）、局部变量的类型，或 `this`——落到该类型的方法、从最近的基类继承的方法（Go 来自嵌入类型，Ruby 来自 include 的模块），或子类型的重写，所以对接口调用 `owners.findById(id)` 会连到实现它的类，`owner.getLastName()` 会连到基类的方法——重载各算各的（抽象的 `value(String?)` 通过它的覆写到达，不会被有方法体的 `value(BufferedSource)` 遮住；Java 或 Kotlin 的字符串、数字只能传给 `Number`、`Comparable` 这类类型，不能传给别的类），覆写方法的重载也包括基类的——两个模块里同名的类（库的 jdbc 和 r2dbc 双胞胎）取文件看得见的那个；闭包里的名字由闭包自己绑定（`test('b', () { … })` 里的 `var request = Request(…)` 不是旁边那个测试的 `request`，Dart、Kotlin、Java、Scala、C#、C++、Go 和 Ruby 都一样，Zig 的 `test` 块也是），闭包没绑定的名字归外层函数；在静态类型语言里，被另一个闭包赋值的变量仍是原来的类型，或者是那里构造出的类型（`late BlocObserver observer;` 之后 `setUp(() { … })` 里的 `observer = MockBlocObserver()`）；库类型（`List`、`String`）的值不会调用项目里同名的方法，除非是项目为它写的扩展方法（C# 带 `this` 参数的、Kotlin 的 `fun String.shout()`、Dart 的 `extension … on`）；方法里的裸调用可能是继承来的方法（子类里的 `getName()`）；Ruby 里单独成句、且方法没有绑定过的裸名字（`setup`）是一次调用，Ruby 文件能看到它 require 的文件又 require 的内容，Dart 库能看到它 import 的库所 export 的内容。Rails 应用的 `app/`、`lib/`、`test/` 和 `spec/` 文件不用 `require` 就能看到彼此的类，和它的自动加载器加载它们一样；一个 spec 能看到 RSpec 在它之前加载的内容——`spec/spec_helper.rb` 和 `rails_helper.rb`、它们 require 的文件，以及 `spec/support/` 下的文件——所以它们引入的辅助方法（`mock_app`）在 spec 里的调用能被连上。Elixir 的裸调用只到达本模块的函数、本文件 `import` 的模块（包括 `import Shop.{Cart, Order}` 这种写法），以及它 `use` 的每个模块注入的内容——那个模块自己的函数、它的 `__using__` 所 import 的模块，以及它再 `use` 的模块注入的内容——所以测试里的 `insert(:user)` 到达它的 case 模板 import 的工厂，绝不到达别的模块里同名的 `insert`，而库的函数（Ecto 的 `from`、ExUnit 的 `assert`）什么也不到达；不带括号的 `user.name` 是读字段，项目没有声明的模块（`:crypto`、`Map`）属于库。Dart 里没有函数体的构造函数（`CounterCubit() : super(0);`、`const BlocProvider({…});`）是一个定义，调用它的类就是调用它；具名构造函数（`factory Temperature.fromJson(…)`）只能按名字调用；混入的方法（`mixin HydratedMixin on BlocBase`）在混入它的类里覆盖基类的同名方法。在 Java、Kotlin、C# 和 Dart 里，项目中的类若某个名字的方法它自己、项目里它的父类（对声明为它的值，还有它的子类）都没有定义，这个方法就来自库——继承 `AbstractMap` 的映射上的 `hashCode` 是 JDK 的——项目给它写的扩展除外。Play 的模板（Twirl 的 `app/views/users/list.scala.html`）就是它编译成的函数 `views.html.users.list`，Scala 控制器以 `views.html.users.list(…)` 调用，Java 控制器以 `views.html.users.list.render(…)` 调用；Play 的反向路由（`routes.HomeController.index`）是生成的代码，并不调用那个 action。只是共用一个文件夹的项目——一个放示例的仓库，每个示例有自己的构建文件，彼此不导入对方的代码——不会调用彼此的函数，不论类名是否相同；从另一个项目导入代码的项目（旁边那个包的示例）与它算作一个项目；而 Java、Kotlin、Scala 或 C# 的导入写的是包名，任何一个示例都可能声明同名的包，所以不会把项目连在一起（本应作为一体的构建，会在上层共用一个构建文件）。`super.save()`（Java、Kotlin、Scala、Dart）和 C# 的 `base.OnInitialized()` 调用的是基类的方法，绝不是调用者自己的覆盖——项目里它上面的类都没有这个方法时，就是库的方法。工厂方法返回的值带有它的函数声明的返回类型（`Users.selectAll()` 是 `Query`），否则——这只是推测，不会因此把方法算作库的——带有调用它的那个类型（`Cart.create()`、Scala 的 `IO.pure(…)` 和 `IO.unit`）；Kotlin 类名调用的是它的伴生对象的成员，包括伴生对象继承来的（`companion object : IntEntityClass<User>(Users)` 之后的 `User.new { … }`）；Scala 里不带括号调用的方法（`cart.total`）也是一次调用——调用的是不写参数列表（或只有隐式参数）的 `def`，或者 Java 方法及其覆写（`toString`），绝不是 `def exitCode()`：Scala 3 只允许带括号调用它，所以 case class 的字段 `r.exitCode` 不会连到这样的方法；不写参数列表的 Scala `def` 带括号调用时，是把它的值再拿来调用（Mill 的 `scalaVersion()`、`super.scalacOptions()`），前提是调用通过它自己的类点出它——裸调用、在 `this` 或 `super` 上调用、或通过对象名调用——因为在别的值上的 `head.get()` 多半是库的方法；它的隐式参数也可以显式传入（`Async.asyncForWriterT(async, L0)`）；当作函数传出去的方法（`xs.foreach(Seg.check)`、`laws.evalOn _`、`macro Macros.impl`）不管有几个参数，都算在那里被用到，但 `_.exitCode`
