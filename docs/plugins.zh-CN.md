# 插件

[English](plugins.md) · **简体中文**

插件为 Clew 补上你需要而 Clew 没有的功能：一个按作者列出项目里 TODO 的命令、一张哪些服务向哪些主题发消息的图、一项你的团队在意的检查。你不必自己写。在提问面板（Ask）里问你的智能体或那里的 ACP 智能体，也可以问通过 MCP 连接到 Clew 的智能体（例如 Claude Code，见 [MCP 与 ACP](mcp-acp.zh-CN.md)）。它来写插件，Clew 来构建，你只需批准一次。

插件就是一个文件：用 Rust 写成的 WebAssembly 组件。它在 Clew 内以接近原生的速度运行，处在一个只有你允许的东西的沙箱里。它无法打开项目之外的文件、启动程序、访问网络或看到你的密钥，因为 Clew 根本没有给它这样做的途径。

## 制作插件

用你自己的话说：

> 帮我做一个插件，列出这个项目里的 TODO 和 FIXME 注释，按最后改动那一行的人分组。

智能体会阅读 Clew 的插件指南，编写插件并构建。编写过程中，它可以在你的项目上试运行插件，并根据编译器的提示修改，直到构建通过。然后 Clew 只问你一次：

> **安装“TODOs by author”？**
> 列出 TODO 和 FIXME 注释，按最后改动每一行的人分组。
> **新增** 一个命令：TODOs by author
> **可以** 读取这个项目的文件 · 读取项目的 git 历史
> *不安装* · *安装*

安装后，这个命令就出现在命令面板里。和其他命令一样，你可以用语音运行它，也可以让智能体替你运行。它的结果以一个页面显示在代码之上，由 Clew 按你的主题绘制。每一行都能打开它所指的那一行代码，用鼠标、键盘或说“打开第三个”都可以。

想改插件，就提出要改什么。智能体会修改它，新版本运行前 Clew 会再问你一次。如果新版本能做的比上一版多，卡片上会写明。

## 插件能添加什么

| | 出现在哪里 | |
|---|---|---|
| **命令** | 命令面板、语音和智能体的 `run_command`。标为 `where = "code"` 的命令还会出现在代码的右键菜单里，并会被告知文件、行和选中的内容。 | 现在 |
| **视图** | 命令显示的内容：标题、Markdown、能打开代码的列表、树、表格、要点、代码、提示。由 Clew 绘制，所以会跟随主题、语言、键盘焦点环、跳转标记和语音。 | 现在 |
| **项目图** | 在“项目图”工具里，与 Clew 自己的图并列。 | 下一步 |
| **检查** | 代码中的发现（行号栏中的标记、边栏中的批注），以及“薄弱点”中的条目。 | 以后 |
| **提问工具** | 提问面板的智能体可以调用的工具。 | 以后 |
| **设置** | 插件自己的选项，在 设置 → 插件 中它的页面上。 | 以后 |

## 插件能做什么

| 权限 | 含义 |
|---|---|
| *（无）* | 处理交给它的内容：运行命令时的文件、行和选中的内容。它可以在两次运行之间保存最多 1 MiB 自己的数据，并写入自己的日志。 |
| **读取这个项目的文件** | 列出项目的文件、读取它们（文本，每个最多 4 MiB），并使用 Clew 的大纲和搜索。只限当前打开的项目，绝不包括项目之外的任何东西。 |
| **读取项目的历史** | 读取 git 的日志和逐行追溯（blame）。不做任何会修改仓库的事。 |

插件永远拿不到网络、其他文件、程序、你的环境变量、你的密钥或你的 AI 服务商。以后的 Clew 版本可能会把其中一些作为单独的权限提供，每一项都会按名称单独征求你的同意。

构建插件时也碰不到这些。被编译的代码读不到你的文件和环境变量，构建时能运行自身代码的，只有几乎每个 Rust 程序都在用的那几个 crate。

Clew 不会轻信插件对自己权限的说法。它从插件的代码中读出权限：也就是代码导入的函数。你没有授予的权限根本不会被链接进去，所以代码没有任何办法调用它。

## 安装、更新、移除

- **设置 → 插件** 列出你的插件。在这里你可以关闭某个插件、移除它、查看它能做什么、阅读它的日志。**从文件安装…** 用来安装别人发给你的插件，它会问你和智能体制作的插件一样的问题。
- 插件文件一旦变化，Clew 就会再问你一次。你批准之后，没有什么能改变插件的文件：Clew 运行的是它自己保存的、你批准过的那份副本，并在每次加载时校验这份副本。
- 插件属于你，而不属于某个项目。它们在你打开的每个项目里都能用。
